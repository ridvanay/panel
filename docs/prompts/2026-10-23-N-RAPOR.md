## 2. Migration SQL'leri

Üç migration var. Hepsi **yalnızca yeni tablo, yeni enum ve yeni indeks** içeriyor.

- Mevcut hiçbir tabloya `ALTER`, `DROP` ya da `RENAME` yok.
- `FOREIGN KEY`'ler yalnızca yeni tablolar arasında.
- Randevu, iletişim formu ve canlı destek kayıtlarına **FK'siz, düz kimlikle** referans veriliyor.

- Yeni çerez bandı (Kabul / Reddet / Tercihler, 6 dil).
- Footer'da "Çerez tercihleri" bağlantısı.
- Onay sonrası yüklenen takip modülü.

**Sıcaklık puanı formülü** (Ayarlar'dan değiştirilebilir, sonuç 0–100 arasında):

```
puan = min(30, okuma dakikası × perEngagedMinute (2))
     + min(30, sayfa görüntüleme × perPageview (3))
     + min(20, (ziyaret sayısı − 1) × perReturnVisit (10))
     + randevu sihirbazına geldiyse bookingPage (20)
     + temas tıklaması varsa contactClick (25)
```

Sıcak eşik varsayılan 50. Okuma süresi, sayfa görünürken gönderilen 15 sn'lik heartbeat'lerden hesaplanır.

## 8. İncelemeler

**security-agent:** kritik yok. 2 orta bulgunun ikisi de düzeltildi:
- Isı haritası iframe `src`'i sahte olay yoluyla dış siteye çevrilebiliyordu. Yol doğrulaması hem toplama ucunda hem iframe'de eklendi.
- Servis hesabı JSON'undaki `token_uri` ile SSRF mümkündü. Artık bu alan yok sayılıyor; istek sabit Google adresine gidiyor ve yönlendirme izlenmiyor.

Düşük bulgulardan düzeltilenler:
- hariç-yol kontrolü normalize edilmiş yolda yapılıyor
- Ads CSV alanlarında formül nötrleme
- `www` origin varyantı

Açık bırakılanlar:
- Origin başlığı tarayıcı dışı istemcilerce taklit edilebilir. Analitik zehirlenmesine karşı IP/oturum başına günlük üst sınır ya da imzalı takip belirteci ileride eklenebilir.
- Talep listesi görüntülemesi audit'e yazılmıyor. Spec yalnızca detay, dışa aktarma ve silmeyi istiyor; her liste yenilemesini yazmak gürültü üretir.

**compliance-agent (KVKK):** madde 1–12 sağlandı. Düzeltilenler:
- pazarlama onayı geri alınınca reklam kimliklerinin silinmesi
- anonimleştirme kapsamının genişletilmesi (randevu, kaynak, atama, açılış sayfası)
- metinlerde "anonim" yerine "takma adlı", 180 gün ve Google (ABD) bilgisi (6 dil)
- aday ziyaretçilerin Ref kodu ve temas tıklamasıyla sınırlanması
- nötr dönüşüm adları
- reklam kimliği 90 gün
- onay 12 ay
- tarayıcı kimliği 180 gün
- yalnızca referrer kökeni
- canlı destek ve iletişim formunda takibin kapatılması
- ham saklama en çok 365 gün

Açık bırakılanlar:
- **Atıftaki açılış sayfası.** Spec atıfta açılış sayfasını açıkça istiyor; aydınlatma metninde belirtilmesi önerildi.
- **Onay metni sürümü.** Metin değişti ama sürüm (`2026-10-23`) artırılmadı. Henüz canlıya alınmadığı için eski onay yok. Canlıdan sonra metin değişirse frontend `CONSENT_VERSION` ile backend `CRM_CONSENT_VERSION` birlikte artırılmalı.

**frontend-agent:** hydration hatası, sonsuz döngü ya da sayfa export ihlali yok. Düzeltilenler:
- pazarlama geri alımında `ctx` içindeki gclid'in gönderilmesi
- "Reddet"te modülün indirilmesi
- CSV indirmede 401 sonrası token yenileme
- sayfa haritasında öneksiz `/` satırı ve erişilebilir tablo yapısı
- ilk görünür kaydırma ölçümü
- `body`'ye sabitlenmiş seçici
- ısı haritası bölgesine klavye erişimi
- filtre ya da sayfa değişince seçimin temizlenmesi
- not eklemenin formu silmemesi
- değişim okları için ekran okuyucu metni
- boş sayı alanının 0 gitmemesi
- gizli dosya girişinin sekme sırasından çıkması
- gereksiz `aria-live`'ın kaldırılması
- düzenin kullanıcı yüklenene kadar beklemesi

**db-agent:** migration'lar spec'e tam uyumlu; kritik ya da yüksek bulgu yok. Düzeltilenler:
- ham SQL zaman parametreleri artık ISO metni + `::timestamp`; DB oturum saat diliminden bağımsız
- özet anahtarı `LEFT(…,300)` ile gruplanıyor, uzun UTM'de çakışma yok
- olay silme parçalı
- içe almada kanal filtresi

Önerilen operasyon notu: prod'da `SHOW timezone;` sonucu UTC olmalı (resmî postgres imajı varsayılanı).

## 9. Bilinçli kararlar ve sınırlar

- **Ayarlar:** yeni tablo açılmadı; `SiteModule(key="crm").settings` JSON'unda duruyor (tema ve acil uyarı deseni). İçe alma imleci `crm-state` anahtarında. `crm` anahtarı modül listesinde görünmüyor.
- **Excel:** yeni paket yasağı nedeniyle `.xlsx` yerine Excel'in doğrudan açtığı UTF-8 BOM'lu CSV veriliyor.
- **gbraid/wbraid:** Google Ads'in CSV şablonu bunları desteklemediği için dönüşüm dosyasına alınmıyor. Sayısı `x-crm-skipped-braid` başlığında bildiriliyor.
- **Görünüm → "Çerez bandı metni":** yeni bant metinleri 6 dilde site sözlüğünden geliyor. Eski tek dilli admin metni artık sitede kullanılmıyor (alanın yanında not var). Bant aç/kapa ve politika bağlantısı ayarları geçerli; bant kapalıysa onay alınamaz ve takip başlamaz.
- **Sayfa ve kaynak tablolarındaki "kişi":** günlük tekillerin toplamı (özet tablosundan). Genel Bakış'taki "Ziyaretçi" KPI'ı ise aralık için gerçek tekil sayı (oturum tablosundan).
- **Flood sayacı:** süreç içi bellekte. Tek backend örneğinde doğru çalışır; çok örnekli kurulumda paylaşımlı depo gerekir.
- **Search Console:** hesap henüz yok. Yalnızca mock'la test edildi. İlk gerçek bağlantıda servis hesabının mülke "Kısıtlı" kullanıcı olarak eklenmesi gerekir.
- **Zamanlayıcılar:** yeni zamanlayıcılar (özet 15 dk, saklama ve anonimleştirme saatlik, talep içe alma 5 dk, Search Console 6 saatte bir kontrol ve günde bir senkron) mevcut süreç içi `setInterval` deseniyle backend'de çalışır. Test ortamında kurulmaz.

## 10. Canlıya alma sırası

Komutlar sunucuda repo kökünden çalıştırılır (Paket G/L yöntemi). Takip **kapalı** gelir. LiveKit, Nginx, `docker-compose.yml` ve `.env` değişmedi.

**1. Yedek**
```bash
docker compose exec -T db pg_dump -U postgres -d saas_prod -Fc -f /tmp/backup_$(date +%Y%m%d%H%M%S).dump
docker compose cp db:/tmp/ ./db-backups-$(date +%Y%m%d)/
```

**2. Migration** (deploy'dan ÖNCE; prod imajında prisma CLI yok, bilinen yöntem). Üç yeni migration uygulanır: `crm_tracking`, `crm_leads`, `crm_search_console`. Yalnızca yeni tablolar.
```bash
DB_URL=$(docker compose exec -T backend printenv DATABASE_URL | tr -d '\r')
NET=$(docker inspect -f '{{range $k,$v := .NetworkSettings.Networks}}{{$k}}{{end}}' $(docker compose ps -q db))
docker run --rm --network "$NET" -v "$PWD/backend/prisma:/app/prisma" -w /app -e DATABASE_URL="$DB_URL" \
  node:20-alpine sh -c "apk add --no-cache openssl >/dev/null && npx --yes prisma@5.22.0 migrate deploy"
# Doğrulama: saat dilimi UTC olmalı
docker compose exec -T db psql -U postgres -d saas_prod -tAc "SHOW timezone;"
```

**3. Backend**
```bash
docker compose up -d --build --no-deps backend
curl -s https://<alan-adi>/api/v1/crm/config   # trackingEnabled:false beklenir
```

**4. Frontend**
```bash
docker compose up -d --build --no-deps frontend
```

**5. Ayarlar'da takibi aç**
1. 2FA'sı açık bir ADMIN hesabıyla Admin → CRM → Ayarlar'a girin.
2. "Ziyaretçi takibi açık" kutusunu işaretleyin; IP modu "Maskeli" kalsın.
3. Gerekirse ofis IP/CIDR ekleyin, bildirim e-postası girin ve kaydedin.
4. Admin → Görünüm → "Çerez Bandı" açık olmalı; "Politika bağlantısı" çerez politikası sayfasını göstermeli. Bant kapalıysa onay alınamaz ve takip başlamaz.
5. Çerez politikası ve aydınlatma metni güncellemeleri (Bölüm 6) yayına alınmadan takibi açmayın.

**6. Kendi cihazını hariç tut**
- Personelin her tarayıcısında bir kez `https://<alan-adi>/?crm_optout=1` açın.
- Admin paneline giriş yapılan cihazlar zaten otomatik hariç tutulur.

**7. Kontrol**
1. Gizli pencerede siteyi açın. Bant "Tümünü reddet / Tümünü kabul et / Tercihler" ile görünmeli.
   - "Reddet" deyin: ağ sekmesinde yalnızca `/api/v1/crm/consent` görünmeli, takip modülü inmemeli.
2. Yeni gizli pencerede "Kabul et" deyin, 2–3 sayfa gezin.
3. 1–2 dakika içinde Admin → CRM → Şu An Sitede'de oturum görünmeli.
4. Genel Bakış'taki tablolar 15 dakikalık özet turundan sonra dolar.
5. `/tr/patient/...` ya da `/tr/checkout` gibi bir sayfayı açın; Ziyaretçiler → detay zaman çizelgesinde **görünmemeli**.
6. Footer → "Çerez tercihleri" → analitiği kapatıp kaydedin; o ziyaretçi CRM'den silinmeli.
7. Log kontrolü:
   ```bash
   docker compose logs --since 30m backend | grep -i "crm" | grep -iv "debug"
   ```
   Hata olmamalı ("CRM günlük özet hesaplaması başarısız" yok).
