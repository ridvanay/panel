## 3. Migration SQL (`backend/prisma/migrations/20261031090000_interpreters/migration.sql`)

Migration yalnızca ekleme yapar. Mevcut tablo ve kolonlara dokunulmaz.

```sql
CREATE TYPE "InterpreterAssignmentStatus" AS ENUM ('ASSIGNED', 'JOINED', 'LEFT', 'REMOVED', 'CANCELLED');
ALTER TYPE "SiteRole" ADD VALUE 'INTERPRETER';

CREATE TABLE "interpreter_profiles" (
    "id" TEXT NOT NULL, "seq" SERIAL NOT NULL, "userId" TEXT NOT NULL, "displayName" TEXT NOT NULL,
    "languages" TEXT[], "timeZone" TEXT NOT NULL DEFAULT 'Europe/Istanbul', "isActive" BOOLEAN NOT NULL DEFAULT true,
    "confidentialityAcceptedAt" TIMESTAMP(3), "confidentialityVersion" TEXT, "notes" TEXT,
    "createdAt" TIMESTAMP(3) NOT NULL DEFAULT CURRENT_TIMESTAMP, "updatedAt" TIMESTAMP(3) NOT NULL,
    CONSTRAINT "interpreter_profiles_pkey" PRIMARY KEY ("id"));

CREATE TABLE "appointment_interpreters" (
    "id" TEXT NOT NULL, "seq" SERIAL NOT NULL, "bookingId" TEXT NOT NULL, "interpreterId" TEXT NOT NULL,
    "language" TEXT NOT NULL, "status" "InterpreterAssignmentStatus" NOT NULL DEFAULT 'ASSIGNED',
    "assignedById" TEXT, "assignedAt" TIMESTAMP(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
    "joinedAt" TIMESTAMP(3), "leftAt" TIMESTAMP(3), "removedById" TEXT, "removedReason" TEXT,
    "createdAt" TIMESTAMP(3) NOT NULL DEFAULT CURRENT_TIMESTAMP, "updatedAt" TIMESTAMP(3) NOT NULL,
    CONSTRAINT "appointment_interpreters_pkey" PRIMARY KEY ("id"));

CREATE TABLE "interpreter_requests" (
    "id" TEXT NOT NULL, "bookingId" TEXT NOT NULL, "language" TEXT NOT NULL,
    "requestedAt" TIMESTAMP(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT "interpreter_requests_pkey" PRIMARY KEY ("id"));

CREATE UNIQUE INDEX "interpreter_profiles_seq_key" ON "interpreter_profiles"("seq");
CREATE UNIQUE INDEX "interpreter_profiles_userId_key" ON "interpreter_profiles"("userId");
CREATE INDEX "interpreter_profiles_isActive_idx" ON "interpreter_profiles"("isActive");
CREATE UNIQUE INDEX "appointment_interpreters_seq_key" ON "appointment_interpreters"("seq");
CREATE INDEX "appointment_interpreters_bookingId_status_idx" ON "appointment_interpreters"("bookingId", "status");
CREATE INDEX "appointment_interpreters_interpreterId_status_idx" ON "appointment_interpreters"("interpreterId", "status");
CREATE UNIQUE INDEX "interpreter_requests_bookingId_key" ON "interpreter_requests"("bookingId");

ALTER TABLE "interpreter_profiles" ADD CONSTRAINT "interpreter_profiles_userId_fkey" FOREIGN KEY ("userId") REFERENCES "users"("id") ON DELETE CASCADE ON UPDATE CASCADE;
ALTER TABLE "appointment_interpreters" ADD CONSTRAINT "appointment_interpreters_bookingId_fkey" FOREIGN KEY ("bookingId") REFERENCES "appointment_bookings"("id") ON DELETE CASCADE ON UPDATE CASCADE;
ALTER TABLE "appointment_interpreters" ADD CONSTRAINT "appointment_interpreters_interpreterId_fkey" FOREIGN KEY ("interpreterId") REFERENCES "interpreter_profiles"("id") ON DELETE RESTRICT ON UPDATE CASCADE;
ALTER TABLE "interpreter_requests" ADD CONSTRAINT "interpreter_requests_bookingId_fkey" FOREIGN KEY ("bookingId") REFERENCES "appointment_bookings"("id") ON DELETE CASCADE ON UPDATE CASCADE;

-- Bir booking'e aynı anda en çok 1 aktif tercüman (Prisma şemasında ifade edilemez; elle eklendi).
CREATE UNIQUE INDEX "appointment_interpreters_one_active_per_booking" ON "appointment_interpreters"("bookingId") WHERE "status" IN ('ASSIGNED', 'JOINED', 'LEFT');
```

> ⚠️ Kısmi unique index Prisma şemasında yok. Bu yüzden **`prisma db push` asla kullanılmamalı**; index silinir. Şema dosyasında da bu uyarı yorum olarak duruyor. Migration `saas_dev`, `saas_test` ve `saas_e2e` veritabanlarına uygulandı.

### 4.4 Tercüman gizlilik taahhüdü (taslak; admin → Tercümanlar → "Gizlilik metni" ekranından TR/EN düzenlenebilir)

Metin değiştiğinde sürüm (EN+TR metninin sha256 özeti) de değişir. Bu durumda her tercüman bir sonraki girişinde metni yeniden onaylamak zorundadır; onay verilmeden token alınamaz.

**TR**
1. Görüşmeler sırasında gördüğüm ve duyduğum her şeyi, hastaların kimlik ve sağlık bilgileri dahil, kesinlikle gizli tutacağım ve kimseyle paylaşmayacağım.
2. Görüşmenin hiçbir bölümünü kaydetmeyecek, fotoğraflamayacak, kopyalamayacak ya da saklamayacağım; kişisel veri içeren not almayacağım.
3. Hiçbir şey eklemeden, çıkarmadan ya da değiştirmeden eksiksiz ve doğru çeviri yapacağım; tıbbi tavsiye vermeyeceğim.
4. Görüşmelere yalnızca üçüncü kişilerin göremeyeceği ve duyamayacağı özel bir ortamdan, kulaklıkla katılacağım; kayıt cihazı kullanmayacak, yerime başka bir kişi ya da araçla çeviri yaptırmayacağım.
5. Öğrendiğim bilgileri yalnızca atandığım görüşmenin çevirisi için ve WM Health'in talimatlarına uygun olarak işleyecek, başkasına aktarmayacağım.
6. Hesabımı yalnızca kendim kullanacak, şifremi ve iki adımlı doğrulamamı güvende tutacak, olası bir veri ihlalini 24 saat içinde WM Health'e bildireceğim.
7. Görüşme kaydediliyorsa sesimin ve görüntümün de kayda gireceğini, atamalarımın ve görüşmeye giriş-çıkış zamanlarımın kayıt altına alındığını biliyorum.
8. Bu yükümlülükler WM Health ile çalışmam sona erdikten sonra da devam eder. İhlalin 6698 sayılı KVKK, Türk Ceza Kanunu ve ilgili mevzuat kapsamında hukuki ve cezai sonuçları olabileceğini biliyorum.

**EN**
1. I will keep strictly confidential everything I see or hear during consultations, including patients' identity and health information, and I will not disclose it to anyone.
2. I will not record, photograph, copy or store any part of a consultation, and I will not take notes containing personal data.
3. I will interpret completely and accurately, without adding, omitting or changing anything, and I will not give medical advice.
4. I will join consultations only from a private place, using headphones, where no third person can see or hear the session; I will not use any recording device or any other person or tool to interpret on my behalf.
5. I will process the information I learn only to interpret the consultation I am assigned to, following WM Health's instructions, and I will not pass it on to anyone else.
6. I will use my account only myself, keep my password and two-factor authentication secure, and report any suspected data breach to WM Health within 24 hours.
7. I understand that if a consultation is recorded, my voice and image will also be included in the recording, and that my assignments, join and leave times are logged.
8. These obligations continue after my work with WM Health ends. I understand that breaching them may have legal and criminal consequences under the Turkish Personal Data Protection Law (KVKK), the Turkish Criminal Code and other applicable law.

Tercüman, görüşme sırasında paylaşılan sağlık verilerinizi yalnızca çeviri amacıyla işler; görüşme kaydedilirse tercümanın sesi ve görüntüsü de kayda girer. Tercüman belgelerinize, notlarınıza ve reçetelerinize erişemez. Hukuki dayanak: açık rızanız ve sağlık hizmetinin sunulması. Haklarınızı md. 11 uyarınca kullanabilirsiniz."

**EN:** "To overcome a language barrier, an interpreter bound by a confidentiality undertaking may join your consultation at your request or your physician's assessment. The interpreter processes the health data shared during the consultation solely for interpretation; if the consultation is recorded, the interpreter's voice and image are also recorded. The interpreter cannot access your documents, notes or prescriptions. Legal basis: your explicit consent and the provision of healthcare. You may exercise your rights under KVKK Art. 11 / GDPR."

## 5. Yapılanlar (özet)

### İş 1 — Rol ve veri modeli
- `INTERPRETER` rolü eklendi. Genel kullanıcı API'si bu rolü atayamaz (422); tercüman hesabı yalnızca Tercümanlar ekranından açılır.
- Üç yeni model: `InterpreterProfile`, `AppointmentInterpreter` (booking başına en çok 1 aktif atama) ve `InterpreterRequest`.
- Hasta talep kutusu rezervasyon sihirbazının 4. adımında, yalnızca `interpreterIncluded=true` olan hekimde görünür. Kapalı veya geçmiş booking için talep 409 ile reddedilir.

### İş 2 — Admin
**Tercümanlar ekranı** (`/admin/telehealth/interpreters`):
- davet (şifre belirleme e-postası) ve daveti yeniden gönderme
- diller, aktif/pasif durumu
- gizlilik onay durumu
- zorunlu 2FA
- rapor ve CSV
- TR/EN gizlilik metni düzenleyicisi

**Booking "Tercüman" kartı:**
- Uygun tercümanlar listelenir: aktif, güncel gizlilik onayı olan, dili uyan, çakışan ataması olmayan.
- Ata / değiştir / kaldır işlemleri `interpreter.assigned` ve `interpreter.unassigned` olarak audit'e yazılır.
- Kaldırmada `removeRoomParticipant` çağrılır ve yeni token verilmez.

**E-postalar** alıcının dilindedir:
- Tercümana giden e-postada hasta adı, şikâyet veya belge yoktur. İçinde yalnızca tarih (tercümanın kendi saat diliminde ve TR saatiyle), dil, doktorun kısaltılmış adı ve panel bağlantısı bulunur.
- Hasta ve doktora da bilgilendirme e-postası gider.

### İş 3 — Tercüman paneli ve oda
- Panel `/[lang]/interpreter` adresindedir (noindex). Akış: 2FA → gizlilik onayı → atamalar. Atamada hasta yalnızca baş harfiyle görünür.
- Katılım penceresi doktorunkiyle aynıdır.
- Oda içinde:
  - 3. kutu "Tercüman · dil" etiketiyle görünür.
  - Katıldı/ayrıldı bildirimleri gösterilir.
  - Doktorun "Görüşmeden çıkar" düğmesi onay penceresi açar. Çıkarma işlemi ataması `REMOVED` yapar, tercümanı odadan atar ve audit'e `interpreter.left` ile `interpreter.removed_by_doctor` yazar.
- Tercüman ekranı:
  - Kayıt başlatma, belge, not ve ekran paylaşımı yoktur.
  - Kayıt açıksa "Bu görüşme kaydediliyor" uyarısı çıkar.
  - QA dinleyici varsa onun uyarısı da gösterilir.
- Tercümanın katılım ve ayrılışı `interpreter.joined` / `interpreter.left` olarak audit'e yazılır (oturum kimliği ve süreyle).
- **Kayıt:** Egress `startRoomCompositeEgress` ile "speaker" düzeninde çalışır. Tercüman gizli olmadığı için composite kayda girer. Egress koduna dokunulmadı.
- **Temizleyici (güvenlik incelemesinden):** 30 saniyede bir çalışır. Geçerli aktif ataması olmayan `interpreter:` kimliklerini odadan atar ve `interpreter.stray_removed` olarak audit'e yazar. Bu sayede çıkarılmış, pasifleştirilmiş veya askıya alınmış bir tercümanın elinde kalan token'la yeniden bağlanması engellenir.

### Açık hukuki kararlar (kod dışı; hukuk danışmanına)

1. **Rıza:** Hasta talep etmeden admin bir tercüman atarsa hastaya "tercümansız devam" seçeneği sunulmalı mı? Hasta talebinde talep açık rıza sayılabilir; admin atamasında rıza yok.
2. **Yurt dışı aktarım:** Türkiye dışındaki tercüman için KVKK md. 9 dayanağı gerekiyor. Tercümanın ülkesinin kaydedilmesi ve taahhütname konusu açık.
3. **Saklama:** Tercüman kişisel verisi ve audit kayıtları için saklama süresi belirlenmeli ve DATA_INVENTORY'ye işlenmeli.
4. **Sözleşme türü:** Tercüman bağımsız çalışan mı, hizmet sağlayıcı mı? Veri işleyen sözleşmesi gerekiyor; tek taraflı taahhüt yetmeyebilir.
5. **Aydınlatma metni:** §4.5'teki ekin `docs/legal/` metnine işlenmesi.
6. **Tercümanın kendi kaydı:** Kayıtta tercümanın ses ve görüntüsü de var. Taahhüdün 7. maddesi bunu bildiriyor; saklama süresinin tercümanı da kapsayıp kapsamadığı netleşmeli.

## 9. Deploy sırası (prod)

1. **Yedek:** PostgreSQL tam yedeği al.
2. **Migrate:** İmajda prisma CLI olmadığı için compose ağında tek kullanımlık bir `node:20-alpine` (+openssl) konteyneriyle `prisma migrate deploy` çalıştır. **`db push` kullanılmaz**; kısmi index silinir.
3. **Backend:** `docker compose up -d --build --no-deps backend`
4. **Frontend:** `docker compose up -d --build --no-deps frontend`
5. **İlk tercüman hesabı:** Admin → Tele-Sağlık → Tercümanlar → "Tercüman ekle". Tercüman davet e-postasıyla şifresini belirler, 2FA'yı kurar ve gizlilik metnini onaylar.
6. **Test görüşmesi:** Ödemesi yapılmış bir test booking'ine tercüman ata. Hasta, doktor ve tercümanla giriş yap; 3. kutuyu, çıkarma işlemini, kaydı ve raporu doğrula.

- **LiveKit konteyneri yeniden başlatılmaz**; LiveKit sunucu ayarları değişmedi.
- Temizleyici backend içinde çalışır. LiveKit iç URL'si (`internalUrl`) tanımlı değilse temizleyici ve "çıkar" işlemi yalnızca uyarı loglar.
