### 4. Talep formu (`/{lang}/request`, `?service=`, `?package=`)

**Alanlar:**

- tercih edilen tarih aralığı;

- ad soyad, e-posta, telefon/WhatsApp (isteğe bağlı);
- mesaj (isteğe bağlı, en çok 1000 karakter), altında şu uyarıyla: "Do not share detailed medical information here; our coordinator will guide you securely.".

**KVKK/GDPR:**
- Aydınlatma metnine bağlantı var; iletişim için açık rıza kutusu zorunlu.
- Mesaj doluysa ayrı bir sağlık verisi açık rızası zorunlu; formda ve sunucuda aynı kural.
- Rıza zamanları kaydedilir; rıza metni sürümünü sunucu atar (`consultation-v1`).
- Mesaj AES-256-GCM ile şifreli saklanır.
- IP ve tarayıcı bilgisi 30 gün, mesaj 365 gün sonra silinir; talep CRM saklama süresi dolunca anonimleşir.

**Kayıt:**
- Talep `consultation_requests` tablosuna yazılır ve CRM'de `CONSULTATION_REQUEST` kanallı bir talep (lead) açılır. Durum takibi admin "Talepler" ekranında yapılır.

- Admin, sağlık rızası geri çekilince mesajı silebilir (`withdraw-health-consent`).

**Admin bildirimi:** AG altyapısı kullanılır (tekil olay anahtarı, yeniden deneme, alıcı başına gönderim; alıcılar "Randevu bildirimi alıcıları" ayarından).
- Konu: "New consultation request #REQ-… — {bölüm}".
- Gövdede bölüm, ülke, dil, tercüman ve tarih aralığı ile "Open request" bağlantısı var. **Ad, iletişim bilgisi ve mesaj yok.**
- Saatlik tavan 30. Tavan aşılınca saatte en çok 1 uyarı e-postası gider.

**Ziyaretçiye onay e-postası** (kendi dilinde, tr→en, kurumsal şablon):

**Spam koruması:**

- Honeypot (`website` alanı).
- Aynı e-posta ve aynı bölüm için 10 dakika içinde gelen ikinci talep kayıt açmaz.

### 5. Türkçenin kaldırılması

**Dil:** `tr` ziyaretçiye `disable-site-locale.ts` ile kapatılır (`enabled=false`; çeviriler, slug'lar ve içerik korunur). Dil seçicide, hreflang'de, sitemap'te ve `llms` dosyalarında görünmez. Varsayılan dil EN.

**Adresler:** `/tr` ve `/tr/*` 301 ile EN karşılığına yönlenir (öneksiz). Yalnızca Türkçe slug'ı olan içerik, mevcut kanonik slug yönlendirmesiyle (308) EN slug'ına gider.

**Sabit Türkçe metinler:** Ziyaretçi tarafındakiler (404, global hata, API hata mesajları, bakım sayfası, paylaş düğmeleri vb.) EN'ye ve çevirilere taşındı.

**E-postalar:** Müşteri e-postalarında tr → en; tek noktada (`toCustomerEmailLocale`). Personel e-postaları ve admin paneli Türkçe kalabilir.

**Yasal sayfalar:** Footer'da yalnızca EN yasal sayfalar kalır; script TR yasal sayfa bağlantılarını çıkarır, sayfa kayıtları silinmez. TR yasal sayfa adresleri EN'ye yönlenir. Metinler değişmedi.

## Canlıya alma sırası

> Script'ler canlı imajda yok. G/L/T yöntemiyle, compose ağında tek kullanımlık `node:20-alpine` konteynerinde çalıştırılır. **Her script önce kuru çalıştırılır ve ilk satırdaki `[hedef DB]` kontrol edilir.**

```bash
DB_URL=$(docker compose exec -T backend printenv DATABASE_URL | tr -d '\r')
NET=$(docker inspect -f '{{range $k,$v := .NetworkSettings.Networks}}{{$k}}{{end}}' $(docker compose ps -q db))
RUN() { docker run --rm --network "$NET" -v "$PWD/backend:/app" -w /app -e DATABASE_URL="$DB_URL" \
  node:20-alpine sh -c "apk add --no-cache openssl >/dev/null && npm ci --silent && npx prisma generate >/dev/null && npx tsx $*"; }
```

1. Dalı master'a al, sunucuda `git pull`.
2. **Migration.** Bekleyen tüm migration'lar uygulanır; AG'ninkiler henüz uygulanmadıysa onlar da:
   ```bash
   docker run --rm --network "$NET" -v "$PWD/backend/prisma:/app/prisma" -w /app -e DATABASE_URL="$DB_URL" \
     node:20-alpine sh -c "apk add --no-cache openssl >/dev/null && npx --yes prisma@5.22.0 migrate deploy"
   ```
3. **Derleme:** `docker compose up -d --build --no-deps backend frontend`.
4. **Dil:**
   - Varsayılan dili doğrula; EN değilse önce `RUN scripts/switch-default-locale-to-en.ts --dry-run`, sonra `--target en`.
   - Ardından `RUN scripts/disable-site-locale.ts` (kuru), sonra `RUN scripts/disable-site-locale.ts --confirm=disable-site-locale --operator="Ad Soyad"`.
